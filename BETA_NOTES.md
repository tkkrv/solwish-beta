# SolWish beta — что изменилось и как запустить

Эта папка — копия проекта для дальнейшей разработки. Исходный `solwish` (сборка для Colosseum) не менялся.

## Запуск (Windows, PowerShell или терминал VS Code)

```bash
cd C:\Users\aitol\solwish-beta
npm install
copy .env.example .env.local
npm run dev
```

Откройте http://localhost:3000. Кошелёк должен быть в сети **Devnet**: в настройках Phantom включите Testnet Mode и выберите Solana Devnet.

## Обязательно перед первым запуском

1. **База данных.** Создайте в Supabase **отдельный проект** для beta и выполните в SQL Editor файл `supabase/migrations/0001_wishes.sql`.
   Почему отдельный: миграция включает защиту RLS. Если включить её в общей базе, версия для Colosseum перестанет создавать вишлисты.
2. **Ключи в `.env.local`:** `NEXT_PUBLIC_SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` (Project Settings → API → service_role).
   Ключ service_role нельзя называть с префиксом `NEXT_PUBLIC_`, иначе он попадёт в браузер.
3. **Деплой.** Создайте на Vercel **новый проект** для этой папки (`vercel` → «Link to existing project? No»).
   Папку `.vercel` из оригинала я не копировал специально: иначе деплой beta перезаписал бы демо для Colosseum.
4. **Git.** История git не копировалась. Вариант: `git init` и новый репозиторий `solwish-beta`, либо ветка `beta` в старом репозитории.

## Версия 0.3: что добавилось

- **«Мои вишлисты»** (`/my`): все вишлисты кошелька — как получателя или создателя, — прогресс, вкладка «Отправленные подарки» (читается из блокчейна).
- **Управление** (`/w/<id>/manage`): изменить название, описание, дату, обложку; закрыть сбор; удалить. Права подтверждаются бесплатной подписью кошелька, без логина.
- **Цель в фиате**: SOL, USD, KZT, RUB, EUR. Курс SOL берётся из CoinGecko (кеш 2 минуты). Каждый подарок записывает в Memo свою сумму в валюте вишлиста на момент перевода, поэтому прогресс не «прыгает» вместе с курсом.
- **Несколько желаний** в одном вишлисте (до 8) с прогрессом по каждому; даритель выбирает, на что дарит.
- **Дата события** и обратный отсчёт.
- **Анонимный подарок.**
- **«Спасибо»**: получатель отвечает на открытку записью в блокчейне.
- **Картинка для Stories** (1080×1920) на странице открытки.
- **Уведомления в Telegram** о новых подарках, в том числе через Blink и QR.

### Обновление базы (обязательно для 0.3)

Supabase → SQL Editor → выполните `supabase/migrations/0002_wishes_v2.sql` **до** `git push`. Без неё создание вишлистов с новыми полями (фиат, желания, дата, сохранение в «Мои») и управление будут падать с ошибкой.

### Настройка Telegram-уведомлений (необязательно)

1. В @BotFather создайте **отдельного** бота для beta (`/newbot`), например `SolWishBetaBot`. Бот основной версии не трогайте: webhook перехватит все его сообщения.
2. В Vercel → Settings → Environment Variables добавьте:
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather;
   - `NEXT_PUBLIC_TELEGRAM_BOT_USERNAME` — имя бота без `@`;
   - `TELEGRAM_WEBHOOK_SECRET` — любая длинная случайная строка.
3. Сделайте Redeploy.
4. Один раз подключите webhook (в Git Bash, подставьте свои значения):

   ```bash
   curl "https://api.telegram.org/bot<TOKEN>/setWebhook" \
     -d "url=https://solwish-beta.vercel.app/api/telegram/webhook" \
     -d "secret_token=<TELEGRAM_WEBHOOK_SECRET>"
   ```

   Ответ должен быть `{"ok":true,...}`.
5. На сайте: «Мои вишлисты» → «Подключить Telegram» → подпись в кошельке → откроется бот → Start.

Уведомление приходит, когда кто-то открывает страницу вишлиста или «Мои вишлисты» (сервер проверяет блокчейн на новые подарки). Без отдельного сервиса-наблюдателя это может быть не мгновенно, если страницу никто не открывает.

## Что сделано по аудиту

**Безопасность**
- Получатель подарка берётся только из базы. Параметр `to` из ссылки больше ничего не решает, неизвестный вишлист → 404.
- Все данные проверяются на сервере (zod): сумма, адрес (только настоящие кошельки), длина текста, размер Memo, обложка только по https.
- Браузер больше не обращается к Supabase напрямую. Запись идёт через сервер по service_role-ключу; SQL-миграция включает RLS.
- Убраны фейковые адреса-заглушки и хранилище с «пионами Айнуры».
- ID вишлистов: `nanoid` (12 символов) вместо `Math.random`.
- Лимит запросов на создание вишлистов (10 за 10 минут с одного IP).
- Найдено при тестах: SPL Memo тратит ~300–400 compute units на байт. Длинная открытка на кириллице могла не пройти. Теперь лимит 140 символов + запас compute в транзакции; проверено в LiteSVM на худшем случае.

**Баги**
- Язык теперь один на весь сайт (cookie), выбор на главной сохраняется везде. Казахский код `kk`, старый `kz` тоже понимается.
- Поле «Для кого сбор» вместо захардкоженного `Creator`.
- `actions.json` и Blink исправлены: ссылки `/w/<id>` раскрываются в Blink, параметры `{amount}`, `{senderName}`, `{message}` подставляются; старые ссылки `/blink?id=` перенаправляются.
- Транзакция подтверждается по blockhash, blockhash обновляется прямо перед подписью; отправка через `sendTransaction` кошелька (лучше работает на мобильных).
- Включена проверка типов при сборке, удалён мёртвый код, `next lint` заменён на `eslint .` (в Next 16 команды `next lint` нет).
- Убран тяжёлый пакет `@solana/wallet-adapter-wallets` (node_modules: 2,2 ГБ → ~0,8 ГБ).

**UX (ориентир — tiplink.io)**
- Светлый минималистичный дизайн, единые токены, иконки lucide, шрифт Inter с казахскими буквами.
- Страница вишлиста: прогресс сбора и стена открыток читаются из блокчейна.
- Оплата с телефона: QR Solana Pay (сумма и открытка уже внутри) с автоматическим обнаружением оплаты; кнопки «Открыть в Phantom/Solflare».
- Подарок-ссылка в стиле TipLink: создать, отправить, забрать в одно касание, вернуть себе неиспользованную.
- Страница открытки `/card/<подпись>` с отметкой «Проверено в Solana».
- Понятные ошибки вместо `alert()`, плашка Devnet со ссылкой на faucet, конфетти после подарка.
- Живое превью при создании вишлиста, 8 готовых обложек, проверка адреса прямо при вводе, QR и кнопки «Поделиться».
- Динамические OG-картинки: в Telegram/WhatsApp/X ссылка показывает название, имя и прогресс сбора.

## Что проверено, а что нет

Проверено в облаке: сборка, типы, линт; API на тестовой базе (валидация, 404, атаки через `to`); сборка и исполнение транзакций подарка, пополнения и claim подарок-ссылки в LiteSVM; вёрстка страниц на десктопе и телефоне на трёх языках; OG-картинки.

Не проверено: реальные транзакции в Devnet с настоящим Phantom (из облака devnet-RPC недоступен), раскрытие Blink в X (нужен публичный домен и регистрация в реестре Dialect). Это стоит прогнать вручную после деплоя.
